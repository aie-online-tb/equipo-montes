# Specs

Cada pieza del sistema nace de una spec. Trabajamos con Spec-Driven Development en versión ligera.

## Cómo funciona

1. **Spec** (`spec.md`): qué queremos y por qué, con criterios de aceptación. No dice cómo.
2. **Plan** (`plan.md`): cómo se va a hacer. Se escribe cuando la spec está aprobada.
3. **Tareas** (`tasks.md`): pasos pequeños y comprobables.
4. **Implementación**: en una rama `nombre/NNN-nombre-corto`, con PR a `develop`.

Una spec la aprueba una persona, nunca Claude. Trello dice qué se hace y cuándo; `tasks.md` dice cómo.
